# Residential Constitution V1

Status: ACTIVE_SECTION_GOVERNANCE

Section: Residential

Date: 2026-06-23

## Core Definition

The Residential section is not a Client Identity System.

Residential does not create a permanent client account layer. It does not require client registration, saved client profiles, stored client preferences, or durable client memory.

The Residential user is understood as:

- visitor
- room participant
- session presence
- fresh intent signal

The Residential section measures current interaction and current need. It does not rebuild a historical client identity archive.

## Current Residential Runtime

The active Residential runtime currently consists of:

- Client Room
- Accessibility Room

These rooms are residential surfaces because they serve visitor/client access and accessibility access without requiring a permanent client account.

## Forbidden Residential Core

The Residential section must not contain:

- client registration
- client login
- permanent client profile
- saved destination memory
- booking
- payment
- case management
- diagnosis
- provider assignment
- session lifecycle management
- medical decision authority
- provider verification

## Governance Boundary

Residential owns its own section governance.

This file does not inherit authority from the ARCHIVE_ONLY global constitution model.

Owner coordination may happen later at convergence points between Residential and other sections, such as reports, signal summaries, or archive reviews. The Owner does not own the Residential constitution.

## Execution Rule

Any Residential change must update the Residential archive layer first when the change affects:

- rooms
- cards
- routes
- signals
- reports
- prompts
- assets
- localization
- external links

No Residential change should silently reintroduce client identity, booking, payment, diagnosis, or permanent client memory.
