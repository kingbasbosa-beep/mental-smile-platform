## Digital Twin Definition

The Residential Digital Twin is an indexed governance layer.

It references existing registries.

It does not recreate them.

It does not duplicate registry content.

It does not execute runtime behavior.

It indexes the current runtime connection status without owning Firebase, Firestore, signals, aggregation, archive writers or routes.

---

## Primary Rule

The Residential Digital Twin must become the primary administrative entry point for future AI assistants.

Future assistants should answer Residential governance questions by consulting the Digital Twin indexes instead of scanning the entire repository.

The Digital Twin is a navigation layer, not a duplicate storage layer.

---

## Usage Model

When a future assistant needs Residential governance information:

1. Start with `RESIDENTIAL_MASTER_REGISTRY_INDEX_V1.md`.
2. Identify the correct registry family.
3. Follow the registry location.
4. Use asset/content/signal indexes for narrowed lookup.
5. Use navigation maps for ownership and governance flow.
6. Avoid broad repository scans unless the Digital Twin explicitly marks a reference as missing or stale.

---

## Non-Duplication Rule

The Digital Twin may include:

- Registry name.
- Registry location.
- Owner.
- Purpose.
- Connected registries.
- Related guides.
- Related operations.
- Related signal families.
- Review status.
- Runtime status.

The Digital Twin must not include:

- Full registry table copies.
- Full card contents.
- Full localization content.
- Full signal row duplication.
- Flutter implementation.
- Runtime execution.
