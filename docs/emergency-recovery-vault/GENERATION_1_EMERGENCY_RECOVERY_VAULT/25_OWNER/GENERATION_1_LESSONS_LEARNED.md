# GENERATION_1_LESSONS_LEARNED

## Technical Lessons
- Active runtime must be protected by exact code, route, signal, Firestore, and asset registries.
- Runtime writes must be minimal, anonymous, and Archive-governed.

## Architectural Lessons
- Direct section-to-section ownership creates confusion; Archive ownership keeps memory safe.
- Capsules work because they separate active truth from historical evidence.

## Governance Lessons
- No Code = No Authority.
- Active Documents are the trusted current truth source.
- Owner Decisions must hold future improvements instead of silently implementing them.

## Economic Lessons
- Rebuildability is a strategic asset.
- White-label and tenant expansion require governance before productization.

## Legal Lessons
- Credentials, identity, diagnosis, and private runtime data must never enter recovery artifacts.

## Ethical Lessons
- Sensitive support signals must avoid profiling and diagnosis inference.
- Historical philosophy must not contaminate current active truth.

## Product Lessons
- The daily Owner workspace should stay warm and lightweight.
- Enterprise dashboard instincts can harm creative operations.

## AI Collaboration Lessons
- Future assistants need reading order, active-document boundaries, and explicit no-legacy rules.

## Most Expensive Mistakes
- Allowing legacy labels and placeholders to remain active too long.
- Letting duplicated routes and destinations blur ownership.

## Most Valuable Discoveries
- Code Gate, Language Guard, Destination Resolution, and capsules made reconstruction possible.

## Decisions That Changed The Future
- Archive owns durable memory.
- Every active item needs code, card, owner, purpose, registry, and digital twin reference.

## Things Never To Repeat
- No active placeholders.
- No uncoded authority.
- No silent Firestore broadening.
- No philosophical noise as runtime truth.
