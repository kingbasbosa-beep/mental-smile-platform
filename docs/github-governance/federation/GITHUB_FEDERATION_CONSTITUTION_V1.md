# GitHub Federation Constitution V1

Status: ACTIVE_GOVERNANCE_FOUNDATION
Date: 2026-07-08
Scope: GitHub as a governed infrastructure federation member

## GitHub Identity

GitHub is an infrastructure federation member of Mental Smile OS.

It is not the product identity by itself.
It is not the official production host by itself.
It is not the long-term memory vault by itself.
It is not the clinical, service, booking, payment, or treatment authority.

GitHub currently serves multiple practical roles because the repository is historically hybrid, but the intended model separates these roles into governed zones.

## Allowed Responsibilities

GitHub may responsibly hold:

- Active Flutter runtime source in the development repository.
- Active governance documentation.
- Active operation reports.
- Temporary GitHub Pages publishing through `gh-pages`.
- Branch-level development history.
- Release and documentation records.
- Workflow definitions for governed automation.
- References to Firebase configuration.
- Recovery and archive references until a dedicated history repository exists.

## Forbidden Responsibilities

GitHub must not become:

- The sole long-term historical dump.
- The official public philosophy website when stale pages conflict with current truth.
- A source of product identity from legacy GitHub Pages.
- A source of product identity from `public-landing`.
- A permanent archive mixed with active runtime without governance labels.
- A production Firebase authority.
- A place where temporary deployment is confused with official production publishing.
- A hidden source of booking, payment, session, diagnosis, or clinical service claims.

## Repository Role Doctrine

The intended federation model separates repository responsibilities:

- Development Repository: active runtime and current governance operations.
- History Repository: historical memory only.
- Documentation/Main Repository: stable documentation and release truth.
- Deployment Surface: generated output only.
- Recovery Archive: frozen recovery packages and rebuild material.

The current repository remains hybrid until separation is explicitly performed.

## Branch Role Doctrine

Branches must be interpreted by role, not by name alone.

- `main` is intended for stable documentation and final governance truth.
- `post-separation-pure-dna-v1` is the active development branch.
- `gh-pages` is temporary public web publishing output only.
- `ai-lab` is a legacy/lab branch.
- `codex/*` branches are task-specific work branches.
- Future history branches must be read as memory, not active product.

## Workflow Role Doctrine

Workflows are infrastructure tools, not product truth.

- Active temporary publishing is owned by the GitHub Pages workflow.
- Firebase workflows may exist as disabled stubs and must not be treated as active production unless explicitly re-enabled by governance.
- Workflows must not redefine product identity.
- Deployment workflows must only publish approved outputs.

## GitHub Pages Doctrine

GitHub Pages is temporary public web publishing only.

Allowed on `gh-pages`:

- Generated `build/web` output.
- `.nojekyll`.

Forbidden on `gh-pages`:

- Source code.
- Governance docs.
- Archive packages.
- README philosophy.
- `public-landing` source.
- Legacy static websites.
- Any stale product identity.

## History Separation Doctrine

Historical material must remain readable, but it must not impersonate current runtime truth.

Old reports, old landing packages, retired systems, and frozen decisions belong to history/archive zones or a future dedicated history repository.

Current product truth belongs to the active constitutional baseline, active section docs, active runtime source, and current deployment workflow.

## AI/Codex Interpretation Rules

AI/Codex must:

- Treat GitHub as a governed federation member.
- Identify whether a file is runtime, governance, archive, deployment, generated output, or legacy before acting.
- Avoid inferring current product identity from old GitHub Pages output.
- Avoid inferring current product identity from `public-landing`.
- Avoid treating `gh-pages` as source code.
- Avoid treating historical archive files as runtime.
- Treat Firebase workflow stubs as disabled unless governance explicitly enables them.
- Prefer `docs/constitutional-baseline/` and active section docs for current architectural truth.
- Treat `lib/`, `assets/`, `web/`, and active config files as runtime truth.

## Final Doctrine

GitHub is a federation member, not an unbounded warehouse.
