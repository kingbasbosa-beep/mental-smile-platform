# APPLICATION AGGREGATION DUAL OUTPUT DOCTRINE V1

Operation ID: OP-APPLICATION-AGGREGATION-DUAL-OUTPUT-DOCTRINE-V1

Status: ACTIVE_DOCTRINE

Mode: DOCUMENTATION_ONLY

Runtime created: NO

Signals connected: NO

Firebase changed: NO

## Purpose

This doctrine defines the dual-output model for future Application Aggregation summary packages.

Application Aggregation remains a summary collection system only.

It does not analyze.

It does not decide.

It does not classify.

It does not recommend.

## Primary Output

Primary Output is the Strategic Planning Receiver Copy.

Purpose:

- support future planning;
- support trend discovery;
- support periodic review;
- support cross-section studies;
- support recommendation work outside Application Aggregation.

Application Aggregation does not perform that analysis itself.

It only prepares the same summary package for Strategic Planning intake.

## Archive Output

Archive Output is the Archive Receiver Copy.

Purpose:

- preserve summary history;
- support continuity;
- support future recovery;
- support replay verification;
- preserve evidence of what summary package was generated.

Archive does not perform planning or optimization.

Archive holds the record.

## Receiver Contracts

### Strategic Planning Receiver Contract

Strategic Planning may receive:

- summary package ID;
- generation timestamp;
- summary window;
- route totals;
- card totals;
- language totals;
- exit-flow totals;
- website click totals;
- category totals;
- section health totals.
- platform-related issue category totals if a future approved summary supports them.
- WhatsApp opened counts.

Strategic Planning must not receive:

- raw events;
- user identity;
- phone numbers;
- emails;
- notebook text;
- suggestion text;
- check-in answers;
- uploaded media;
- authentication data.
- complaint text;
- legal or professional misconduct details.

### Archive Receiver Contract

Archive may receive:

- the same summary package;
- package checksum or version reference if implemented later;
- generation timestamp;
- dispatch timestamp;
- retention marker;
- replay marker.
- platform-related issue category totals if a future approved summary supports them.
- WhatsApp opened counts.

Archive must not receive:

- raw events;
- user identity;
- personal content;
- media payloads;
- authentication data.
- complaint text;
- legal or professional misconduct details.

## Dispatch Package

A future dispatch package may contain:

- package ID;
- operation ID;
- generated at;
- generated by authorized operator;
- summary window type: hourly / daily / weekly / manual;
- summary window start;
- summary window end;
- summary totals;
- complaint category counters only;
- WhatsApp opened counters only;
- report files or structured summary payload;
- receiver list:
  - Strategic Planning Receiver Copy
  - Archive Receiver Copy

The two receiver copies must be identical at the Application Aggregation layer.

No interpretation, scoring, ranking, or transformation is allowed before dispatch.

No direct Legal Receiver Copy exists.

Legal Governance may only receive complaint-related summaries later through Archive or a separately approved governance flow.

## Replay Recovery Rules

Replay recovery means the Archive can later prove what summary package existed.

Allowed replay recovery data:

- summary package ID;
- summary window;
- generated timestamp;
- dispatch timestamp;
- summary totals;
- receiver copy markers;
- report version.

Forbidden replay recovery data:

- raw event streams;
- user timelines;
- user profiles;
- personal content;
- notebook text;
- suggestion bodies;
- check-in answers;
- uploaded image/media content.

Replay recovery supports continuity only.

It does not reconstruct user behavior.

## Archive Holding Rules

Archive holds:

- summary packages;
- package metadata;
- continuity evidence;
- replay recovery markers;
- historical copies.

Archive does not:

- analyze;
- recommend;
- optimize;
- decide;
- classify users;
- create alerts.

## Strategic Planning Intake Rules

Strategic Planning receives:

- the summary package;
- the summary window;
- the count/status totals;
- the section health summary.

Strategic Planning may later perform:

- analysis;
- trend discovery;
- planning;
- recommendations;
- cross-section studies;
- periodic reporting.

Strategic Planning must treat the package as aggregated summary material, not personal data.

## No Runtime Rule

This doctrine does not create:

- runtime aggregation;
- signal emitters;
- Firestore collections;
- Firebase rules;
- Monitoring connections;
- Administrative connections;
- automatic dispatch.

## Final Rule

Application Aggregation creates identical summary packages for:

- Strategic Planning;
- Archive.

Application Aggregation does not transform the package for either receiver.
