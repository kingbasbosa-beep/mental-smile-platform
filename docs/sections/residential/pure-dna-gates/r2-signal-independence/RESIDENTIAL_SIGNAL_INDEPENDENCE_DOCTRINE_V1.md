## Purpose

R2 establishes the Residential Signal Independence Doctrine.

R1 created the first signal code system and signal-capable UI registries. R2 corrects the architectural relationship between UI cards and Signal cards.

A Signal Card is not a UI card.

A Signal Card is a minimal strategic counting and routing unit.

---

## Core Doctrine

Signal Cards exist to count and route actions.

They are owned by Strategic / Analytics governance and must contain only what the future analytics, aggregation, archive and Strategic summary layers need.

Signal Cards must not contain:

- UI layout.
- Button color.
- Visual placement details.
- Widget styling.
- Prompt text.
- Maintenance instructions.
- Marketing ownership.
- Full localization copy beyond a reference label.
- Technical implementation notes.

Those details belong to UI Technical Cards, Tool Cards, Link Cards, App Cards, Content Cards, Localization Cards or Technical Cards.

---

## Approved Signal Card Fields

Every Residential Signal Card may contain only:

- Signal Card ID.
- Signal Code.
- Source Section.
- Source Surface.
- Source Element Reference.
- Signal Family.
- Counted Action.
- Archive Magnet Code.
- Archive Destination.
- Aggregation Destination.
- Strategic Summary Destination.
- Privacy Class.
- Retention Class.
- Runtime Status.
- Review Status.

---

## Ownership Rule

| Layer | Owner | Owns |
|---|---|---|
| UI Technical Cards | Product / UI / Technical section | What appears on screen. |
| Signal Cards | Strategic / Analytics governance | What is counted and where it is routed. |
| Archive Magnet Map | Archive governance | Where signal packages are stored. |
| Aggregation Map | Monitoring / Strategic readiness governance | Where counts are grouped. |
| Strategic Summary Map | Strategic Planning / Owner intelligence | Where reviewed insight is delivered. |

---

## R1 Correction

R1 remains preserved as source evidence.

R2 does not delete or rewrite R1.

R2 creates corrected registries that separate:

1. UI description.
2. Signal counting.
3. Archive routing.
4. Strategic summary routing.

---

## Final Rule

No single card owns the whole truth.

Each layer owns one responsibility and references the others.
