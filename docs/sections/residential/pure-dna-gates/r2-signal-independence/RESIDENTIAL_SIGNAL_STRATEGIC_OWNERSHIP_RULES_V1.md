# RESIDENTIAL_SIGNAL_STRATEGIC_OWNERSHIP_RULES_V1

Status: ACTIVE

Gate: R2

---

## Purpose

Define ownership boundaries for Residential Signal Cards and their surrounding governance layers.

---

## Ownership Matrix

| Object | Owner | Responsibility | Not Responsible For |
|---|---|---|---|
| Minimal Signal Card | Strategic / Analytics Governance | Counted action, routing, privacy, retention, review status. | UI design, localization, widget styling. |
| UI Technical Card | Product / UI / Technical Owner | Display, semantics, accessibility, visible text and component reference. | Aggregation, analytics, Strategic summary ownership. |
| Archive Magnet Code | Archive Governance | Archive grouping and storage classification. | UI meaning or analytics interpretation. |
| Aggregation Destination | Monitoring / Strategic Readiness | Count grouping destination. | Runtime collection, UI behavior. |
| Strategic Summary Destination | Strategic Planning / Owner Intelligence | Reviewed insight destination. | Raw signal execution. |

---

## Strategic Rules

1. A Signal Card is a Strategic / Analytics object.
2. A UI Technical Card can reference a signal but cannot own signal truth.
3. Archive Magnet Codes must be stable once approved.
4. Strategic summaries must not receive raw private content.
5. Notebook and image anchor signals must remain count-only unless future privacy governance explicitly approves more.
6. Complaint/support signals require review before Strategic circulation.
7. Exit signals must not be interpreted as negative user judgment without reviewed context.

---

## Review Classes

| Review Class | Applies To |
|---|---|
| ACTIVE_REVIEWED | Normal signal card approved for future runtime connection. |
| HIGH_PRIVACY_REVIEW | Notebook, private local utility and sensitive support surfaces. |
| SAFETY_REVIEW | Complaints, blocked states, safety or support friction. |
| STRATEGIC_REVIEW | Aggregated summaries before Owner delivery. |
